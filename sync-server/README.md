# CoworkPal Sync Server

用于保存 CoworkPal 用户数据快照的轻量 Docker 服务。服务不依赖数据库，每次上传都会保留一个版本，默认每位用户保留最近 30 个版本。

## 部署

1. 复制 `.env.example` 为 `.env`，配置一个至少 32 个字符的管理员令牌。`COWORKPAL_USERS_JSON` 可保留 `{}`；需要兼容旧客户端时，也可继续预配置用户令牌。
2. 执行 `docker compose up -d --build`。服务监听 `0.0.0.0:18080`，局域网管理看板地址为 `http://192.168.124.13:18080/`。
3. 客户端可直接填写 `http://192.168.124.13:18080`；也可使用 Caddy、Nginx 或服务器现有网关把 HTTPS 域名反向代理到 `127.0.0.1:18080`。
4. 用户在 CoworkPal 设置页填写服务器地址和用户名，点击“申请令牌”。管理员在看板批准后，客户端会自动保存令牌和用户唯一 ID，同时上传首次完整备份。

服务器局域网健康检查地址为 `http://192.168.124.13:18080/health`，反向代理目标为 `http://127.0.0.1:18080`。HTTP 同步内容不加密，建议仅在可信局域网使用；公网部署建议配置 HTTPS。

最小 Caddy 配置示例：

```caddy
sync.example.com {
    reverse_proxy 127.0.0.1:18080
}
```

部署后可执行 `curl http://192.168.124.13:18080/health` 检查服务，预期返回 `{"status":"ok"}`。

## 管理看板

浏览器打开同步服务根地址（例如 `http://服务器局域网地址:18080/`），输入 `COWORKPAL_ADMIN_TOKEN` 即可处理客户端令牌申请并查看全部用户。看板可查看和复制用户令牌，也可重置、停用或验证管理员发放的令牌；重置后的新令牌只有通过服务端认证检查后才会提示复制成功。每个用户都有稳定唯一 ID。看板顶部汇总用户数、备份数、累计在线、笔记、日报、体检和成就；每个管理员发放的用户行右侧直接显示“删除”按钮，点击用户行可查看令牌、最多 30 份历史备份、备份信息、工坊状态、云端数据、应用设置、硬件配置和模块等级。管理员可从历史记录中选择一份执行“推送还原”。

同一用户名和设备标识再次申请令牌时，服务端会复用最近一次备份对应的用户唯一 ID，避免仅因更换令牌而产生重复用户。环境变量 `COWORKPAL_USERS_JSON` 中预配置的兼容用户不能在看板删除，需要修改环境变量后重新部署。

管理员发放的令牌使用由 `COWORKPAL_ADMIN_TOKEN` 派生的密钥进行 AES-256-GCM 加密后保存。部署后不要随意更换管理员令牌；更换后已有令牌仍可用于认证，但无法在看板查看或用于设备恢复，需要逐一执行“重置令牌”。环境变量中预配置的兼容令牌可查看和用于恢复，但不能在看板直接重置或停用。

## 设备重装恢复

1. 在旧设备或管理看板复制用户唯一 ID。
2. 新设备填写服务器地址和用户唯一 ID，点击“恢复历史令牌”。
3. 管理员在“令牌申请”中确认该用户和新设备后批准恢复。
4. 客户端自动保存原令牌，并立即拉取最新完整快照，其中包含设置、工坊、日报、体检、专注记录、成就和笔记。

服务端为每位用户最多保留 30 个完整快照，超过上限时自动删除时间最早的版本，并通过 `GET /v1/snapshot/history` 向已认证客户端返回历史版本清单。管理员推送历史版本后，服务端会把该版本提升为最新快照并保留待还原任务；在线客户端通过现有 30 秒轮询自动拉取、完整还原并确认任务。客户端离线时任务会保留到下次连接。

管理员令牌仅保存在当前浏览器标签页的 `sessionStorage` 中，关闭标签页后自动清除。请勿将管理员令牌配置为任一用户令牌；使用 HTTP 时应限制服务只对可信局域网开放。

## 数据与备份

- 数据保存在 Docker 卷 `coworkpal-sync-data`。
- 管理员发放的用户凭据和申请状态保存在卷内的 `auth-state.json`；客户端完成首次备份后，服务端会移除申请记录中的明文令牌，只保留令牌摘要。
- 每个用户目录由用户名的 SHA-256 摘要命名，日志不会输出令牌或快照内容。
- 备份服务器时请同时备份该 Docker 卷。
- `MAX_VERSIONS` 可以把保留数量调低，但服务端会将其限制在 `1` 到 `30` 之间。

服务接口：`GET /health`、`POST /v1/token-requests`、`GET /v1/token-requests/:id`、`GET /v1/snapshot`、`PUT /v1/snapshot`、`GET /v1/snapshot/history`、`GET /v1/snapshot/restore-pending`、`POST /v1/snapshot/restore-pending/:id/ack`、`GET /v1/admin/snapshots`、`DELETE /v1/admin/users/:userId`、`POST /v1/admin/users/:userId/snapshots/:revision/restore`、`POST /v1/admin/token-requests/:id/approve`、`POST /v1/admin/token-requests/:id/reject`。快照接口使用用户 Bearer Token 鉴权，管理接口使用管理员 Bearer Token 鉴权。
