## 4. New and Optimized Content

### UI 线程 COM apartment 固定为 STA

- 之前：Tauri setup 创建 `AppState` 时会在 UI 线程构造 `SysinfoAdapter`。Windows 版 `sysinfo 0.30.13` 的组件刷新通过 WMI 调用 `CoInitializeEx` 默认值（MTA）；WebView2 随后要求同一线程使用 STA，返回 `RPC_E_CHANGED_MODE`。
- 现在：CoworkPal 在进入 Tauri Builder 之前主动调用 `CoInitializeEx(COINIT_APARTMENTTHREADED)`，并保持 apartment guard 到 Tauri 事件循环结束。
- 原因：WebView2、Tao 窗口和 OLE UI 功能要求 UI 线程保持 STA，这是 Windows 桌面 UI 的正确线程模型。
- 影响范围：所有延迟创建的 Tauri WebView 窗口，包括主界面、设置、关于、宠物和监控条。

### 移除无效的 Windows sysinfo 温度回退

- 之前：`Components::new_with_refreshed_list()` 会启动 Windows WMI/ACPI Thermal Zone 探测。
- 现在：Windows 使用空的 `Components::new()`；Linux/macOS 继续刷新平台组件温度。
- 原因：该 Windows 传感器只返回标记为 `Computer` 的 ACPI thermal zone，并非 CPU Package 温度，CoworkPal 的筛选逻辑本来就不会采用它。
- 影响范围：CPU/GPU 温度继续由 CoworkPal 内置硬件监控助手及其他现有适配器提供，不会因删除该无效回退而丢失有效读数。

### Tao 文件拖放兼容保护

- Windows 延迟窗口统一设置 `drag_and_drop(false)`，避免 Tao 为未使用的文件拖放功能调用 `OleInitialize`。
- CoworkPal 的窗口拖动使用自身鼠标事件和 Tauri `startDragging`，不受影响。

## 5. Fixed Bugs

### 点击“打开主界面”时 WebView2 创建失败并退出

- 错误现象：日志记录 `failed to create webview`、`HRESULT(0x80010106)`，Release 进程随后退出。
- 触发条件：Windows 设备上首次延迟创建主窗口，且 UI 线程此前被硬件组件探测初始化为 MTA。
- 根因：同一线程的 COM apartment 不能从 MTA 改成 STA；WebView2 初始化因此失败。
- 受影响范围：主界面、设置和任何首次创建的 WebView2 延迟窗口。
- 修复方式：先固定 UI 线程为 STA，再阻止 Windows `sysinfo` ACPI/WMI 组件探测，并关闭未使用的 Tao 原生文件拖放。
- 回归风险：未来若重新引入在 UI 线程强制初始化 MTA 的库，仍可能产生相同冲突；新增测试会覆盖 STA 初始化约束，但目标硬件兼容仍需真机验证。
- 验证证据：最新 Release 通过 Windows UI Automation 调用 CoworkPal 系统托盘图标，日志记录 `opening main window route="dashboard"` 和 `main window opened route="dashboard"`；进程保持响应，枚举到 `WRY_WEBVIEW`、`Chrome_WidgetWin_0/1`、`Chrome_RenderWidgetHostHWND`，且新日志中没有目标错误。
