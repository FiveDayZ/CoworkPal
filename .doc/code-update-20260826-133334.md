## 5. Fixed Bugs

### 部署端口定义不一致

- 现象：部署配置期望从 `18080` 访问，但容器内部服务、健康检查和文档仍使用 `8080`，容易导致重部署后代理目标或健康检查指向错误端口。
- 触发条件：按 `18080` 配置服务器端口并重建容器。
- 根因：主机映射端口和容器内部端口采用了两套默认值。
- 影响范围：同步服务 Docker 部署、健康检查和反向代理说明。
- 修复方法：将 Env、Compose、Dockerfile、Node 默认端口、文档和客户端本机测试地址全部统一为 `18080`。
- 回归风险：远程服务器的现有反向代理若仍指向旧端口，需要同步改为 `127.0.0.1:18080`。
- 验证证据：Compose 容器显示 `18080/tcp -> 127.0.0.1:18080`、环境变量为 `PORT=18080`、健康状态为 `healthy`，`/health` 返回 HTTP 200。
