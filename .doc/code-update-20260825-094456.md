## 4. New and Optimized Content

1. **使用 LHM 稳定标识识别 CPU**
   - 之前：主要依赖节点文本和 `ImageURL` 判断 CPU；部分 LHM 版本、主题或设备树缺少 CPU 图标，Intel 型号名称也不一定包含独立的 `CPU` 单词，导致整个 CPU 子树被忽略。
   - 现在：优先读取 `HardwareId` 和 `SensorId`，识别 `/intelcpu/...`、`/amdcpu/...` 等稳定标识，再使用图标和名称回退。
   - 原因：LHM 的标识符比厂商型号文本和界面图片稳定。
   - 影响范围：新版 LHM REST 数据中的 Intel/AMD CPU 温度。

2. **读取 RawValue 和显式传感器类型**
   - 之前：仅解析格式化 `Value`；某些 LHM 版本或区域设置可能把格式化值显示为 `-`、带单位或本地化文本。
   - 现在：优先读取数值型 `RawValue`，缺失时再解析 `Value`；存在 `Type` 时只接受 `Temperature`，避免同名 Load/Power 传感器被当作温度。
   - 原因：这是 LHM 新版 `data.json` 为外部系统提供的稳定机器可读字段。
   - 影响范围：不同 LHM 版本和区域设置下的温度解析。

3. **扩展旧版 CPU/GPU 识别回退**
   - 之前：名称回退主要覆盖 Ryzen、Processor 和含 CPU 的名称。
   - 现在：补充 Intel Core、Threadripper、EPYC、Athlon，以及 NVIDIA/ATI/Intel GPU 图标和 Intel UHD/Iris 名称。
   - 原因：兼容不提供 ID 字段的旧版 REST 树和更多硬件家族。
   - 影响范围：旧版 LHM 数据结构和不同 CPU/GPU 型号名称。

4. **保持 TrafficMonitor 的保守边界**
   - TrafficMonitor 通过 LibreHardwareMonitor 的 `HardwareType::Cpu` 与 `SensorType::Temperature` 读取 CPU 传感器；本次改动使用 REST 中等价的 HardwareId/SensorId/Type 信息。
   - 未恢复 ACPI Thermal Zone 回退，因为它不是 CPU Package/Core 温度。

未新增、替换或升级依赖；未修改配置键、持久化结构或外部事件格式。

## 5. Fixed Bugs

### 5.1 部分设备的 LHM CPU 子树无法识别

- 错误现象：LHM 能提供 CPU 温度，但 CoworkPal 在节点没有 CPU 图标或名称不命中旧关键字时返回 N/A。
- 触发条件：REST 节点以 `HardwareId`/`SensorId` 标识 CPU，节点文本为具体处理器型号，且 `ImageURL` 缺失或不同。
- 根因：解析器未读取 LHM 已提供的稳定硬件和传感器标识。
- 影响范围：部分 Intel、AMD 和旧版/新版 LHM 组合。
- 修复方法：解析 HardwareId、SensorId、Type、RawValue，并扩展兼容名称。
- 回归风险：低；无 ID 的旧结构仍保留原有图标/名称/温度组回退。
- 验证证据：新增的 Intel HardwareId/SensorId + RawValue、AMD EPYC 旧结构测试均通过。

### 5.2 格式化值不可解析时丢失有效温度

- 错误现象：`Value` 为 `-` 或本地化文本时，即使 `RawValue` 有有效温度也返回 N/A。
- 触发条件：新版 LHM REST 同时给出机器值与格式化显示值，但显示值不可直接转成浮点数。
- 根因：旧解析器只读取 `Value`。
- 影响范围：使用新版 `data.json` 的设备和区域设置。
- 修复方法：优先读取 RawValue，使用 Value 作为兼容回退。
- 回归风险：低；仍执行 0 到 125 摄氏度的合理性校验。
- 验证证据：测试输入 `Value: "-"`、`RawValue: 57.25`，实际解析得到 `57.25`。
