## 4. New and Optimized Content

### 4.1 任务栏右键极简模式

- 之前：任务栏右键菜单不能直接进入或退出极简模式。
- 现在：菜单第二项为可勾选的“极简模式”，托盘菜单和原生任务栏菜单共享同一行为。
- 进入后：隐藏 CoCat、关闭悬浮监控条、保留原生任务栏监控、开启低功耗、关闭内置提权温度助手。
- 退出后：恢复进入前保存的上述配置，并清除恢复快照。
- 极简模式中与该模式冲突的 CoCat、监控条和任务栏显隐菜单项会禁用。

### 4.2 内存路径优化

- 之前：原生任务栏右键菜单借用隐藏的主 WebView 窗口，打开菜单可能启动 WebView2。
- 现在：任务栏菜单使用 CoworkPal 自身的轻量 Win32 隐藏窗口作为菜单所有者，菜单取消后也不会留下 WebView2 子进程。
- 进入/退出极简模式会保存设置并自动重启，使已存在的 WebView2 进程和窗口资源真正释放。

### 4.3 重启兼容

- 应用内重启会设置内部重启标记。
- 新进程最多等待约 5 秒接管单实例互斥锁；普通重复启动仍立即退出。
- 成功接管后立即清除内部重启标记。

## 5. Fixed Bugs

### 5.1 极简模式重启后应用消失

- 现象：首次实现调用 Tauri 重启后，旧进程退出，但新进程可能被单实例互斥锁误判为重复实例并退出。
- 触发条件：从菜单切换极简模式并立即重启。
- 根因：Tauri 先拉起新进程再结束旧进程，旧进程短时间内仍持有命名互斥锁。
- 修复：仅对应用内重启子进程执行有界互斥锁重试，并关闭重试过程中获得的重复句柄。
- 风险：异常情况下重启最多等待约 5 秒后退出；普通启动路径不等待。
- 证据：Release E2E 中进入和退出两次切换均观察到进程 ID 改变，设置状态正确持久化。

### 5.2 极简模式右键菜单可能拉起 WebView2

- 现象：仅打开原生任务栏右键菜单也会创建隐藏主 WebView，增加内存占用。
- 触发条件：在原生任务栏监控区域右键。
- 根因：原实现使用 `ensure_webview_window("main")` 作为 Tauri 菜单所有者。
- 修复：改用轻量 Win32 菜单所有者和原生 `TrackPopupMenuEx`，按菜单位置分发既有动作。
- 风险：共享菜单位置发生调整时需同步原生位置映射。
- 证据：Release 运行中菜单正常出现；极简状态主进程无子进程，工作集约 34.3 MiB。
