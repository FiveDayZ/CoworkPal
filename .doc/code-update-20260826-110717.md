## 4. New and Optimized Content

1. 之前行为：任务栏 `WM_PAINT` 仅通过 GDI `CreateFontW + DrawTextW` 输出文字；即使字体文件固定，栅格化质量仍难以接近 TrafficMonitor 的 DirectWrite 路径。
2. 新行为：首次绘制时创建隔离的 `IDWriteFactory5`，把 EXE 内嵌字体注册到 DirectWrite 内存字体集合；不会安装字体，也不会依赖系统字体集合。
3. 新行为：复用 `ID2D1DCRenderTarget` 并绑定任务栏窗口的 HDC，通过 `IDWriteTextLayout + DrawTextLayout` 输出双行三列文字。
4. 渲染参数：9pt、Normal 字重、水平和垂直居中、禁止换行、字符级省略号、DPI 感知尺寸；透明色键窗口使用灰度抗锯齿，避免 ClearType 彩边。
5. 兼容行为：DirectWrite 初始化、字体加载、HDC 绑定或绘制失败时，清理画布并调用原 GDI 路径；回退日志仅记录一次，避免周期刷新刷屏。
6. TrafficMonitor 参考：沿用其 DirectWrite 文本格式、文本布局和 Direct2D 绘制思路；未引入 DComposition，因为当前 DC 渲染目标已能在现有任务栏子窗口中正确显示。

依赖调整：

- `windows 0.61.3`：仅开启项目已使用的同一绑定包中的 Direct2D、DirectWrite、Direct2D Common 和 DXGI Common 特性。
- `windows-numerics 0.2.0`：用于 `DrawTextLayout` 的强类型 `Vector2` 坐标。该包此前已由 `windows` 间接锁定，本次没有增加新的传递包；上游为 Microsoft `windows-rs`，许可为 MIT OR Apache-2.0。
- 替代方案：使用不安全内存转换可避免直接依赖声明，但类型安全和可维护性更差；改用 `DrawText` 会放弃方案 1 要求的 `IDWriteTextLayout` 路径。

## 5. Fixed Bugs

- 现象：固定字体版仍使用 GDI，用户观察到任务栏文字不够清晰。
- 触发条件：任务栏监控启用并由原生窗口周期刷新时。
- 根因：原生绘制后端仍是 `DrawTextW`，没有使用 TrafficMonitor 同类的 DirectWrite 文本布局和 Direct2D 栅格化。
- 影响范围：Windows 原生任务栏监控文字；主界面、悬浮监控条和存储数据不受影响。
- 修复方法：改用 DirectWrite 内存字体集合和 Direct2D DC 目标，保留原 GDI 回退。
- 回归风险：不同 Windows 版本、DPI、任务栏主题和显示器仍可能出现细微栅格差异；Windows 10 尚未实机验证。
- 验证证据：DirectWrite 字体集合测试确认内嵌字体族存在；当前 Windows 11 运行时没有记录 GDI 回退，原生窗口 392 x 96 物理像素并成功输出完整双行三列文字。
