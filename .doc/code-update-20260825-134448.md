## 4. New and Optimized Content

1. 以前任何数据文件读取错误都会在 `AppState` 中退回默认对象；现在读取失败会中止状态初始化，不再允许后台监控把默认工坊和空历史覆盖到磁盘。
2. 每个 JSON 存档维护 `backups/<文件名>.last-good.bak`。首次读取旧存档时建立备份，后续最多每 5 分钟刷新一次，避免大型历史文件每次采样都产生双倍写入。
3. 主文件损坏或丢失时，优先恢复完整临时文件或最后有效备份；没有有效恢复源时保留原文件并返回错误，不再自动重建为默认值。
4. 临时文件和备份均先完整写入并执行 `sync_all`，再原子替换目标文件。
5. `APPDATA`/`XDG_DATA_HOME` 不可用时拒绝启动存储，不再静默转向临时目录创建一套全新数据。
6. `catId` 只在首次为空时生成。已有 ID 不再因 SMBIOS UUID 查询结果变化而被替换，同时已有 ID 时不再启动 PowerShell 查询 UUID。

## 5. Fixed Bugs

### 存档偶发全部重置

- 现象：重启后历史记录消失，工坊回到 1 级。
- 触发条件：启动时任一已有 JSON 因瞬时锁定、权限、磁盘错误或内容损坏而读取失败。
- 根因：加载层静默返回默认对象，后台监控随后持续保存，最终把临时读取故障固化为永久数据丢失；损坏 JSON 路径也会直接用默认值重建。
- 修复：禁止已有文件失败后回退默认值；增加最后有效备份和完整临时文件恢复。
- 回归风险：无法读取且没有任何有效恢复副本时，应用会拒绝初始化，而不是带着空数据启动。该行为用于优先保护数据。
- 证据：`corrupted_json_without_recovery_is_not_replaced_with_default`、`recovers_corrupted_json_from_last_good_backup`、`recovers_missing_primary_from_complete_temp_file` 均通过。

### 用户 ID 可能随硬件 UUID 变化

- 现象：SMBIOS UUID 变化时，旧实现会替换已有 `catId`。
- 影响：当前 `catId` 并不是 `save.json` 或 `work_logs.json` 的索引键，因此不是本次工坊重置的直接原因，但 ID 本身确实不够稳定。
- 修复：仅在 `catId` 为空时生成一次并持久化。
- 证据：`existing_cat_id_does_not_change_with_smbios_uuid` 和重启持久化测试通过。
