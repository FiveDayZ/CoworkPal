### 4.2 任务栏菜单生命周期修复

- 之前：异步任务只把原生 `HMENU` 句柄传入主线程闭包；Tauri `Menu` 所有者可能在原生菜单循环结束前被释放。
- 现在：主线程闭包持有 `Menu`，直到 `TrackPopupMenuEx` 返回后才释放。
- 原因：原生句柄必须由其 Rust/Tauri 所有者在整个模态菜单循环期间保持有效。
- 影响范围：任务栏原生监控窗口的右键菜单，不改变托盘菜单动作定义。

### 4.3 可诊断的主窗口打开流程

- 可区分“菜单未派发”“窗口创建失败”“导航事件失败”和“窗口已成功显示”几个阶段。

## 5. Fixed Bugs

### 任务栏菜单点击“打开主界面”后程序退出

- 现象：部分设备上 CoworkPal 启动正常，但从任务栏监控右键菜单点击“打开主界面”后整个程序退出。
- 触发条件：从嵌入任务栏的原生监控窗口打开 Tauri 菜单，并在菜单所有者生命周期结束后继续使用其 `HMENU`。
- 根因：Tauri `Menu` 对象未被移入主线程菜单闭包，导致 `TrackPopupMenuEx` 使用期间存在原生句柄提前失效风险。
- 修复：在闭包内持有 `menu` guard，菜单循环结束后再释放。
- 影响范围：任务栏监控右键菜单；系统托盘菜单不使用这条原生句柄路径。
- 回归风险：不同 Windows 版本和显卡驱动下的窗口消息时序仍可能不同。
- 验证证据：Release EXE 自动打开原生菜单并点击第一项，command ID 为 `1013`；随后日志记录 `main window opened route="dashboard"`，`CoworkPal` 主窗口可见且进程仍存活。
