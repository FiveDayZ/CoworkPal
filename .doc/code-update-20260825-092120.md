## 4. New and Optimized Content

1. **LibreHardwareMonitor REST 解析**
   - 之前：Rust 字段未映射 LHM JSON 的 `Text`、`Value` PascalCase 字段，只能解析纯数字，实际 `54.5 °C` 形式容易得到空值。
   - 现在：显式兼容 PascalCase/camelCase 字段，并解析带单位的温度值。
   - 原因：匹配 LHM 实际 `/data.json` 数据结构。
   - 范围：启用 LHM 数据源时的 CPU/GPU 温度。

2. **参考 TrafficMonitor 的硬件树约束和传感器优先级**
   - 之前：没有可靠地区分 CPU、GPU、主板、磁盘和其他温度节点。
   - 现在：只在 CPU/GPU 硬件子树内采集；CPU 优先 `Core Average`、`CPU Package`、`Tctl/Tdie`、`Core Max`、核心传感器，GPU 优先 `GPU Core`，再回退到标准 GPU/Edge/Hotspot 温度。
   - 原因：避免不相关传感器或负载值混入温度结果。
   - 范围：LHM REST 和旧版 WMI 通道。

3. **移除不可靠的 ACPI CPU 温度回退**
   - 之前：Windows `Thermal Zone Information` 机身/平台热区会被换算并显示为 CPU 温度。
   - 现在：完全移除 PDH Thermal Zone CPU 回退；系统组件仅接受 CPU/package/core 等标签，并显式拒绝 ACPI/thermal zone 标签。没有可靠 CPU 传感器时返回 `None`，前端显示 N/A。
   - 原因：ACPI 热区不是 CPU Package/Core 温度，数值可能相差数十摄氏度。
   - 范围：Windows CPU 温度和来源标签。

4. **GPU 温度和缓存可靠性**
   - 之前：LHM 只提供 CPU 结果；NVIDIA 查询失败后可能继续显示旧缓存；多 NVIDIA GPU 未明确选择主设备。
   - 现在：LHM 同时返回 CPU/GPU 温度；NVIDIA 查询失败时清空缓存；多卡按显存总量选择主 GPU，NVIDIA 温度不可用时再使用 LHM GPU 温度。
   - 原因：支持 AMD/Intel GPU，并避免陈旧值和多卡随机选择。
   - 范围：GPU 温度及 NVIDIA 设备信息。

5. **采样与界面说明**
   - 之前：LHM 缓存刷新间隔 5 秒，界面将系统/热区来源统称为“估算”。
   - 现在：LHM 刷新间隔 2 秒，界面区分“高精度”和“系统传感器”，无可靠 CPU 结果显示 N/A。
   - 原因：改善温度时效性，并使来源说明与真实可靠性一致。
   - 范围：硬件采样节奏和界面文本。

未新增或升级第三方依赖，`package.json`、`pnpm-lock.yaml` 和 Rust 依赖清单均未修改。

## 5. Fixed Bugs

### 5.1 ACPI 热区被误报为 CPU 温度

- 错误现象：本机 ACPI `\\_TZ.TZ01` 返回约 `345 K`，旧换算链路显示约 `71.85 °C`，但该值不是 CPU Package/Core 温度。
- 触发条件：LHM 未运行且 Windows Thermal Zone 性能计数器可用。
- 根因：PDH 热区值被无条件当作 CPU 温度回退。
- 影响范围：CPU 温度显示、温度告警及依赖 CPU 温度的统计。
- 修复方法：删除 PDH Thermal Zone 温度字段和换算函数，同时过滤 sysinfo 中的 ACPI/thermal zone 标签。
- 回归风险：没有 LHM 或可靠系统 CPU 组件传感器的机器会显示 N/A，这是有意的保守行为。
- 验证证据：实时适配器探针输出 `cpu=None source=None gpu=Some(56.0)`，未再输出旧的约 `71.85 °C` ACPI 值；对应筛选单元测试通过。

### 5.2 LHM REST 温度字段与单位解析不完整

- 错误现象：实际 LHM JSON 使用 `Text`、`Value`，温度常带 `°C` 单位，旧反序列化/解析可能无法得到值。
- 触发条件：通过 LHM REST Web Server 读取标准 `data.json`。
- 根因：字段命名映射和数值解析与实际 JSON 格式不一致。
- 影响范围：LHM CPU 温度来源，及新增的 GPU 温度来源。
- 修复方法：添加字段重命名/别名和带单位数值解析，并按硬件树选取传感器。
- 回归风险：不同 LHM 版本仍可能出现未覆盖的新标签；未知标签只在明确 CPU/GPU 温度组内参与保守平均。
- 验证证据：REST PascalCase、带单位、非温度值隔离及 WMI CPU/GPU 测试均通过。

### 5.3 NVIDIA 温度旧缓存和多卡选择不稳定

- 错误现象：`nvidia-smi` 后续失败时可能持续显示旧温度；多卡时取首行不一定是主要独显。
- 触发条件：NVIDIA 查询暂时失败，或系统安装多张 NVIDIA GPU。
- 根因：失败未覆盖缓存，结果选择使用首个可解析行。
- 影响范围：GPU 温度和设备显示。
- 修复方法：每次到期查询直接替换缓存，并按显存总量选取设备。
- 回归风险：显存最大的 GPU 不一定是用户当前渲染设备，但比依赖输出顺序更确定。
- 验证证据：多 GPU 选择单元测试通过；本机实时探针读取 GPU `56.0 °C`。
