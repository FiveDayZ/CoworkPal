## 4. New and Optimized Content

1. 独立端口
   - 之前：Compose 默认占用 `127.0.0.1:8080`，容易与服务器面板或其他管理服务冲突。
   - 现在：默认使用 `127.0.0.1:18080`，容器内部仍监听 `8080`。
   - 原因：避免域名或端口误指向 phpMyAdmin，并保留内部服务兼容性。

2. 安全绑定
   - 默认 `COWORKPAL_SYNC_BIND=127.0.0.1`，服务只允许服务器本机反向代理访问。
   - 如确有直接暴露端口的需求，可显式修改绑定地址；默认不扩大公网攻击面。

3. 完整环境变量
   - `.env.example` 现在包含绑定地址、端口、管理员令牌、预配置用户、版本保留数和申请上限。
   - 本地 `.env` 已生成 96 字符随机管理员令牌，并由 `.gitignore` 排除。

4. 文档一致性
   - 部署步骤、示例反向代理目标和 Caddy 配置均统一为 `127.0.0.1:18080`。

## 5. Fixed Bugs

- 现象：访问预期的 CoworkPal 服务地址时出现 phpMyAdmin 登录页。
- 触发条件：CoworkPal 与服务器现有服务共用或错误代理到 80/443/8080 入口。
- 根因：部署端口和反向代理目标未与现有服务明确隔离。
- 修复：CoworkPal 默认改用仅本机监听的 18080 端口，并在示例配置和文档中统一反向代理目标。
- 回归风险：服务器若仍将域名代理到旧端口，远程页面仍不会改变；重新部署后必须同步修改反向代理。
- 验证证据：独立测试容器的 `/health` 返回正常，根页面标题匹配 CoworkPal 且不包含 phpMyAdmin。
