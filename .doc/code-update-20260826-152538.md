## 4. New and Optimized Content

### 4.1 自动备份设置即时保存

- 之前：勾选“自动备份上传”或修改上传间隔只更新页面临时状态；页面卸载后再次读取磁盘旧配置，因此开关恢复未选中。
- 现在：控件变化后调用现有 `updateSyncConfig` 保存完整同步配置，并用服务返回值刷新页面状态。
- 原因：让界面状态与持久化配置保持一致。
- 影响范围：客户端“设置 > 云端数据备份”的自动上传开关和上传间隔。

### 4.2 保存状态和错误回退

- 保存期间禁用开关和间隔选择，避免短时间内并发写入。
- 保存成功显示“自动备份设置已保存”。
- 保存失败时重新读取已保存配置；若读取也失败，则回退到操作前状态并显示错误。

### 4.3 浏览器开发环境配置保持

- 之前：非 Tauri 环境每次调用 `getSyncConfig` 都返回默认值，无法验证页面切换后的配置保持。
- 现在：浏览器开发环境在模块生命周期内保存配置副本，并在读写时返回副本。
- 该改动只用于开发和浏览器回归验证，真实 Tauri 环境继续调用原有 Rust 命令。

## 5. Fixed Bugs

### 自动备份开关切换页面后被取消

- 现象：勾选自动备份后切换到其他页面，再回到设置页，开关恢复未勾选。
- 触发条件：只操作自动备份控件，没有再次点击上方同步配置保存按钮，然后切换页面。
- 根因：控件仅调用 React 状态更新，没有调用同步配置持久化命令；页面重新挂载时读取到旧配置。
- 影响范围：自动备份启用状态和上传间隔的跨页面保持。
- 修复方法：控件变化时立即调用 `updateSyncConfig`，并处理写入期间禁用、成功提示和失败回退。
- 回归风险：快速连续操作由禁用状态保护；真实桌面磁盘写入路径沿用既有 Rust 命令，但本次未在打包后的 Tauri 应用中人工复测。
- 验证证据：浏览器中保存服务器地址和虚拟令牌，开启自动备份，切换到控制台后返回设置页；DOM 显示开关仍为 checked，间隔仍为 30 分钟，控制台无错误或警告。截图见 `.doc/evidence-auto-backup-persistence-20260826.png`。
