## 4. New and Optimized Content

### Windows COM 兼容处理

- 之前：`WebviewWindowBuilder` 使用 Tao 默认的原生文件拖放支持。Tao 在每次创建窗口时调用 `OleInitialize(None)`，要求当前 UI 线程处于 STA 模式。
- 现在：Windows 下创建 CoworkPal 延迟窗口时明确设置 `drag_and_drop(false)`，Tao 不再进入原生文件拖放初始化分支。
- 原因：某些设备或驱动先把 UI 线程初始化为 MTA，随后调用 `OleInitialize` 会返回 `RPC_E_CHANGED_MODE`。该错误与主界面业务逻辑、路由或 WebView2 页面内容无关。
- 影响范围：`main`、`pet`、`monitor-bar`、`pet-panel`、`taskbar-monitor` 等经统一窗口管理器创建的延迟窗口。
- 兼容性：CoworkPal 的标题栏、宠物和监控条拖动由鼠标事件与 Tauri `startDragging` 实现，不依赖 Tao 的文件拖放处理。

## 5. Fixed Bugs

### 点击“打开主界面”或“设置”后进程退出

- 错误现象：日志在 `opening main window route="dashboard"` 或 `route="settings"` 后立即记录未处理 panic，程序重新启动或退出。
- 触发条件：首次创建主窗口时，UI 线程已经以 MTA 模式初始化 COM，Tao 又尝试通过 `OleInitialize` 初始化 STA/OLE 文件拖放。
- 根因证据：用户日志明确包含 Tao `window.rs:109` 的 `RPC_E_CHANGED_MODE`；本地依赖源码显示该行只位于 `if drag_and_drop` 分支内，并直接建议禁用 drag and drop。
- 修复方式：统一窗口构建器在 Windows 下执行 `builder.drag_and_drop(false)`。
- 回归风险：CoworkPal 不再接收系统文件拖入窗口的 Tao 事件；项目当前未使用此功能。
- 验证证据：修改后的 Release EXE 从任务栏原生菜单打开 dashboard，日志出现 `main window opened route="dashboard"`，主窗口可见且进程继续存活。
- 未验证部分：产生原错误的设备尚未安装并运行新构建，不能把目标设备结果标记为已通过。
