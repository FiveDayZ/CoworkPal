## 4. New and Optimized Content

1. 以前用户必须由管理员在环境变量中手工生成并传递令牌；现在客户端填写服务器地址和用户名即可提交申请。
2. 服务端生成独立的申请 ID 和领取凭据，管理看板只显示用户名、设备标识和申请时间，不显示领取凭据或访问令牌。
3. 管理员点击“发放令牌”后，客户端在设置页每 10 秒检查一次；即使设置页未打开，Tauri 后台也会每 30 秒检查一次。
4. 客户端领取后先原子保存访问令牌，再自动上传首次完整备份；首次上传失败时保留令牌，用户仍可手动重试。
5. 动态用户和申请状态写入 Docker 卷内 `auth-state.json`。首次成功上传后删除申请记录中的明文访问令牌，只保留访问令牌摘要。
6. 同名用户申请的新令牌映射到同一备份身份，因此可用于新增设备而不会在总览中重复显示用户。
7. 继续兼容 `COWORKPAL_USERS_JSON` 预配置用户；该变量现在允许使用空对象 `{}`。

## 5. Fixed Bugs

### 窄屏用户名与备份状态重叠

- 现象：360 px 视口下，较长用户名会伸出身份列并覆盖“已备份”状态。
- 条件：用户名较长且看板宽度进入移动断点。
- 根因：身份文本容器缺少 `min-width: 0`，网格列无法收缩文本。
- 修复：为 `.identity > div` 增加最小宽度约束，使长用户名稳定省略。
- 风险：仅影响文本收缩，不改变数据或交互。
- 证据：修复后 360 px 视口 `scrollWidth=345`、`innerWidth=360`，截图中用户名省略且不再重叠。
