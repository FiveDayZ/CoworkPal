## 4. New and Optimized Content

1. 之前行为：任务栏绘制请求系统字体 `Microsoft YaHei Light`。Win10 和 Win11 的字体文件版本、字体回退、ClearType 设置可能不同，因此相同代码会出现字宽、字重和清晰度差异。
2. 新行为：EXE 内嵌固定的 `Noto Sans CJK SC Regular 2.004` 子集，首次绘制时使用 `AddFontMemResourceEx` 注册为当前进程私有字体，之后始终用 `Noto Sans CJK SC`、9pt、`FW_NORMAL` 绘制，不要求用户安装字体。
3. TrafficMonitor 参考：检查的上游提交为 `5efd2159af8117301a2b6a755897aaa995887678`。其简体中文默认字体是微软雅黑，字号 9pt，普通字重，GDI `DEFAULT_QUALITY`；CoworkPal 对齐了字号、字重和质量参数。
4. 许可选择：没有直接打包微软雅黑，因为其字体文件不允许随应用自由再分发。选用 SIL OFL 1.1 的 Noto Sans CJK SC；相比完整字体的 16,437,364 字节，仅保留任务栏所需字符，最终为 62,280 字节。
5. 替代方案：继续依赖系统微软雅黑无法解决 Win10 / Win11 字体版本差异；打包完整 CJK 字体会无必要地增加约 16 MiB；新增字体依赖包也没有收益。本方案没有新增运行时依赖或传递依赖。

## 5. Fixed Bugs

- 现象：Win10 与 Win11 上任务栏监控文字外观不同。
- 触发条件：系统提供的 `Microsoft YaHei Light` 字体版本、字体回退或渲染默认值不同。
- 根因：原实现仅传入系统字体名称，没有随 CoworkPal 提供字体文件。
- 修复：将固定字体子集编译进 EXE，进程内私有注册并按固定字体族绘制；注册失败时才回退到系统微软雅黑。
- 回归风险：不同 Windows 版本、DPI 和 ClearType 栅格器仍可能产生亚像素级差异，但字形、字宽、字重来源已经固定。
- 验证证据：GDI 注册测试通过；当前系统未安装 Noto Sans CJK SC，但 release EXE 能正常绘制任务栏文字，证明不是依赖系统字体。
