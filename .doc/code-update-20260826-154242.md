## 4. New and Optimized Content

1. 辅助监控输出由调用用户的 `%TEMP%` 改为 `%ProgramData%\CoworkPal\HardwareMonitor`。
   - 旧行为：主进程生成普通用户临时目录路径，提升权限后的辅助进程再用提升账户的临时目录进行校验。
   - 新行为：主进程与提升后的辅助进程使用 Windows 跨账户一致的公共应用数据目录。
   - 原因：使用其他管理员凭据确认 UAC 时，两侧 `%TEMP%` 不一致，辅助进程会以退出码 2 拒绝路径。
   - 范围：仅内置 CPU/GPU 温度辅助进程的本地 JSON IPC。

2. 输出文件名增加进程 ID 和毫秒时间戳，避免不同启动实例读取短时间内遗留的旧样本。

3. 新增一次性诊断日志：
   - 主日志记录辅助进程输出路径和异常退出码。
   - CPU 温度为空时，辅助进程记录 CPU 硬件名、温度传感器名及原始值；Tauri 层将其写入 `%APPDATA%\CoworkPal\logs\coworkpal.log`。
   - 相同诊断在单次辅助进程生命周期中只记录一次，避免采样循环刷屏。

4. 辅助进程增加内部 `--validate-output-path` 自检参数，并继续拒绝用户临时目录、嵌套目录和任意路径。

## 5. Fixed Bugs

### 不同 UAC 账户下 CPU 温度始终为空

- 现象：勾选“内置硬件监控”后，任务栏 CPU 温度仍显示 `--℃`。
- 触发条件：普通用户启动 CoworkPal，UAC 提升时使用另一个管理员账户；普通用户与提升账户的临时目录不同。
- 根因：Rust 主进程把普通用户 `%TEMP%` 路径传给辅助进程，而辅助进程按提升账户的 `Path.GetTempPath()` 校验，路径被拒绝并以退出码 2 结束；旧日志只记录“已启动”，没有记录立即退出。
- 影响范围：使用不同管理员凭据提升权限的 Windows 设备；同一账户直接提升的设备通常不受影响。
- 修复方法：IPC 改用所有账户一致的 ProgramData 目录，并记录辅助进程退出码和传感器诊断。
- 回归风险：ProgramData 目录被系统策略禁止创建或读取时仍会失败，但现在主日志会记录目录创建错误或辅助进程退出码。
- 验证证据：路径自检接受 ProgramData 直接子文件并拒绝 `%TEMP%`/嵌套路径；本机辅助进程普通权限读取 CPU 为 `null` 且生成传感器诊断，提升权限后同一路径读取 CPU `94.625℃`、GPU `64℃`，退出码均为 0。
- 未完成证据：尚未在截图中的实际问题设备上安装并复测。
